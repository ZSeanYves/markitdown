
# Native-only 文本转换库：底座升级、算法整合与性能验收计划

## 1. 产品目标与固定边界

定位为：**在明确的文本转换契约下，提供质量可靠、速度快、内存和安装体积可控的 Native 转换库与 CLI。**

“60% 性能、40% 质量”用于安排研发投入。日常转换质量是硬门槛，通过后才比较性能；不允许通过少提取内容、降低资源检查、跳过图片资产或缩减结构来获得速度优势。

本轮固定以下决策：

- **Native-only**：支持 Linux x86_64、macOS arm64；删除产品的 Wasm 分发承诺、兼容实现及相关验收分支。
- **两种交付**：通过 `moon install` 安装 CLI；通过 `ZSeanYves/markitdown/lib` 导入 Native 库。本轮不准备独立预编译下载包。
- **自研核心为主**：社区库及其他语言成熟实现用于算法参考、差分验证、测试语料和少量有价值的运行时复用。
- **小型 FFI 按需**：保留有明确必要性的底层能力；本轮不引入 PDFium 等完整生产解析后端。
- **文本范围保持**：保留现有格式、Office/ODF 语义、PDF 文本与几何、图片资产、来源、Markdown/Debug/RAG。OCR、音频转录、扫描识字继续排除。
- **控制维护成本**：不建设通用解析框架、插件系统、浏览器排版引擎、公式计算器、文档编辑器、全局文档缓存或后台服务。
- **自动化统一 `.mbtx`**：可由 `moonx` 启动验证脚本，脚本测试实际 Native 产物。产品安装入口改为 `moon install`；当前官方已将 `moonx` 收敛到 Wasm。[工具链说明](https://www.moonbitlang.com/updates/2026/09/21/index)、[安装命令](https://moonbitlang.github.io/moon/commands.html)

“完整底座升级”指覆盖所有现有转换路径的正确性、资源管理和执行协议；对已经满足要求的实现，允许保留并提交验证证据，不要求为了重构而重写。

## 2. 目标架构与公共接口

保留薄根入口、公共 `lib`、私有 `internal` 的分工，最终只有一条转换执行链：

```text
Input
  → 转换会话：资源所有权、预算、取消、临时文件
  → 检测与轻量探测
  → 单一异步解析入口 / 受控 pull
  → 格式语义 → 公共 IR / Pipeline
  → Markdown / Debug / RAG
  → 收集器或异步 Sink
```

### 执行与资源管理

- 将当前统一 Registry 中残留的同步注册、异步注册和同步投影收敛为一种解析协议。读取、解析入口、pull 推进和 Sink 异步；扫描、解码、语义计算保持同步。
- 移除异步 Reader 进入转换前的整份输入物化。Path、Bytes、Text、Reader 都使用同一受限输入访问协议。
- Path 文件由转换会话显式关闭；调用方 Reader 仍由调用方管理。正常结束、取消、读取失败、写入失败都释放文档内缓存、文件及临时数据。
- 缓存仅限单次转换，明确容量、键、所有权和淘汰规则；不得因为命中缓存绕过当前请求预算。
- 不能流式完成的跨页、跨记录语义，使用有界摘要或受限临时文件。禁止把全量内存缓存伪装成流式支持。
- 收集 API 允许内存随最终输出增长；Sink 路径不额外保留完整输出。来源、资产和 RAG 元数据同样纳入预算。
- 硬性错误不得触发宽松回退：取消、I/O、CRC、非法编码及资源超限直接终止；格式修复只处理明确定义的可恢复语法问题，并留下诊断。

### API 与模式

- 保留异步 `convert`、版本化入口、现有 Input 构造方式和 façade 自有类型。
- 在公共 façade 增加异步 `convert_to_sink`，提供受背压控制的写入与完成回调，返回不包含完整正文的转换摘要；不要求消费者导入内部包。
- 同步 Reader 构造方式只作输入回调适配，不保留同步转换执行器。
- 将现有资源上限集中登记，并补齐解压、解析工作量、输出、缓存和临时文件预算；既有默认限额不得因性能测试而放宽。
- 保留 `balance`、`accurate`、`stream` 的现有用户语义。内部将保真策略与交付方式分开：`accurate` 保留额外语义，`stream` 不成为降低质量的捷径。
- 保留领域错误与退出分类；将当前可能到达 `abort` 的生产失败路径改为可返回的错误。公开接口变动提供迁移说明及接口 golden。
- 能力表、CLI 帮助、文档和路由检查来自同一登记源；不再保留失真的 Wasm 能力声明。

## 3. 完整底座升级与算法工作

### A. 输入、编码、压缩和公共原语

| 范围 | 本轮实施 | 边界 |
|---|---|---|
| 输入与随机读取 | 有界分块读取、短读处理、明确 EOF/I/O 区分、减少重复打开及 bytes/string 转换 | 不默认引入 mmap；只有测量证明必要才单独实验 |
| 编码与位置 | 增量解码只保留未完成字符；统一 Unicode scalar 校验；区分原始 byte、UTF-16 和行列位置 | 支持当前承诺编码，不建设通用猜编码系统 |
| ZIP/DEFLATE | 保留增量 inflate；缓存、transient、visitor 共用完整性与预算检查；中央目录及规范路径只索引一次 | 保留 CRC、路径碰撞、解压比例、条目数与按需读取；不扩大压缩格式范围 |
| 公共扫描原语 | 统一真正重复的边界检查、实体/转义、数字解码、span 和预算扣减 | 至少对应两个现有消费者或一个已测热点，不抽象万能 AST |

首先为已发现的静态风险建立复现测试：ZIP 缓存绕过较小预算、XML 数值实体溢出、无效 UTF-8 的静默字符替换、非 BMP 字符导致位置单位混用。未复现前不将它们报告为已确认漏洞，修复前必须明确预期行为。

### B. XML、HTML、Markdown 与结构化文本

- **XML 为主要共用基础层**：建立私有、可暂停、有深度限制的 token cursor，支持必要的命名空间、属性、混合文本和来源范围。消费者按需建立小树或局部索引。
- 按“包元数据与关系 → Office → ODF/EPUB → 独立 XML”顺序迁移重复扫描器，修复引号内 `>`、实体单次解码、前缀重绑定等问题。
- 删除 XML 重复 tokenization/DOM 构造以及 HTML prepare 的重复解析；统计信息由同次扫描产出。
- HTML 保持现有文档提取和受控恢复范围；Markdown 保持当前 CommonMark/GFM 风格、脚注/frontmatter 等契约，优先改进 delimiter、嵌套和异常输入处理。
- JSON 收敛重复的语法验证与数字扫描，保留数字词法、键顺序及既有重复键策略。JSONL 复用列索引，减少重复读取，同时保持输出顺序。
- YAML 预算覆盖 alias/merge 的**逻辑展开量**，不能只限制实际节点数；TOML 保留现有表与键索引，重点减少切片和解码分配。
- 流式事件和树构造可共用词法内核，但不同语言不共享一套通用 AST。

算法和测试参考优先选择社区候选，以及 [Expat](https://github.com/libexpat/libexpat)、[cmark-gfm](https://github.com/github/cmark-gfm)、[YAML test suite](https://github.com/yaml/yaml-test-suite)、[toml-test](https://github.com/toml-lang/toml-test)。只导入当前格式契约相关内容，不自动扩张为完整标准支持。

### C. Office、ODF、EPUB、MIME 与其他格式

- 包格式共用 ZIP、XML、路径和关系索引，格式语义继续由各自 reader/lowering 负责。
- 清理 ZIP、包层 bytes、text、DOM 的重复驻留；只缓存确实反复使用的小 part。
- XLSX 按 worksheet/row 处理；ODF 对重复行列进行受限消费，避免预先展开；EPUB 按 spine/chapter 消费和释放。
- 保留合并单元格、公式缓存值、隐藏内容策略、notes/comments、链接、图片和来源；不加入公式重算、宏或排版。
- MIME 改为 bytes range 与边界扫描，按需解码附件，减少 raw message/body 的重复存储。预算错误不能转成宽松 raw fallback。
- IPYNB、字幕、CSV/TSV、TeX/RST/AsciiDoc 复用已经验证的编码、JSON、HTML、文本扫描原语；保留既有格式边界及时间信息。

### D. PDF 专项：本轮性能重点

按以下依赖顺序推进，每一步独立对照：

1. **轻量探测和解析会话**  
   PDF probe 只检查 header、xref、catalog 和 page-tree 所需事实，返回可复用会话；移除路由前完整提取文档的行为。

2. **按需对象访问**  
   xref 保存 offset、generation、ObjStm 索引；从可达页面和资源读取对象。stream 保存范围，避免完整对象反复 bytes/string 转换。ObjStm 解压结果按文档预算缓存。

3. **受限解压与恢复**  
   内容、CMap、字体、对象流都通过有界增量解压。限制 token、嵌套、对象、页面、图形栈与 Form 深度。修复扫描有独立工作量上限，不能吞掉 I/O、取消或超限错误。

4. **单次内容解释与文字解码**  
   一套内容流解释器同时生成文字、图片引用及 marked-content 信息；文字只解码一次，同时得到字符、advance 和诊断。annotation 解析一次后派生链接。

5. **文档内字体与 CMap 复用**  
   以对象身份及解码参数缓存字体、ToUnicode、CMap、ObjStm；共享映射只解析一次，缓存失败结果，禁止全局跨文档缓存。

6. **逐页生命周期**  
   页面提取后进入同一 lowering/pipeline，再释放流与 fragment。需要跨页页眉页脚判断时，保存受限页面事实至临时存储，避免同时持有完整页面模型和完整 IR。

7. **几何与阅读顺序补全**  
   完整处理六元仿射矩阵、旋转、CropBox/继承页面框、字形 advance；在此基础上修正阅读顺序、链接关联和简单表格。保留 CJK、垂直文字、ActualText、图片及 Unicode 校验。

参考 [PDF.js](https://github.com/mozilla/pdf.js)、[PDFBox](https://github.com/apache/pdfbox) 与 `pdflite` 的相关算法；Poppler/PDFium 用于离线文本和几何对照。本轮不引入第二条 PDF 转换链，也不建设 PDF 渲染器。

### E. Pipeline、渲染与运行成本

- 避免 event、block、DocumentIR、renderer model 多份完整表示同时驻留；让纯语义 pass 使用同一批次/页面协议。
- 清理重复遍历、字符串拼接、无效 source_ref 构造及小对象分配；只在实际消费时生成昂贵诊断详情。
- RAG、资产命名和来源顺序必须稳定，不能因流式化改变引用关系。
- CLI batch 默认保持串行复用、单任务及时清理；本轮不新增通用线程池或常驻 worker 协议。通过多进程及库重复调用验证并行部署能力。
- 优化安装后的 executable 及依赖占用；实验、语料、调试产物不进入发布包。FFI 清单记录必要性、所有权、传递依赖和移除条件。

## 4. 质量与性能验收

### 先修复验收器，再冻结基线

当前外仓共有 **515 条 main、403 条 quality、17 条 accurate**；benchmark 有 **126 条 accepted、9 条缺失候选**。实施时重新核对清单及哈希，保留外仓已有工作。

- 全部现有有效契约都必须执行；`reference` 标签不能成为跳过既有行为的理由。预期拒绝的输入必须匹配明确错误。
- manifest 缺文件、重复 ID、未知信号、非法行、零测试均失败；统计总数、筛选、退役、执行和失败。
- RAG 使用 JSON 结构断言，检查正文、chunk、source/asset 引用和诊断。
- 正文、debug、provenance、stdout、stderr 分别断言，禁止拼接后匹配造成误通过。
- 每次使用新输出目录；检查资产集合、引用可达性和哈希；失败也保存完整摘要。
- PDF “10 个中成功 8 个”的宽松测试改成逐文件契约；TN 2194 保留硬门槛。
- 旧 fake runner 证据只用于验证测试工具，不能算产品或安装验收。

### 同质量比较规则

- baseline/candidate 使用同一输入、模式、限额、资产要求和输出目标。
- 对照文本、结构、顺序、元数据、来源、资产、诊断及失败行为。
- 无语义变更时输出指纹一致；正确性修复允许变化，但需分类、审定预期并说明 golden 更新原因。
- 外部库是参考，不是绝对真值；差异以格式契约、规范和人工确认裁决。
- 上轮不同输入、不同提取量的 HTML/Markdown/XLSX 比较不进入同质量倍率结论。先解释输出差异，再纳入性能排名。

### 性能协议与目标

分别测量：

- 安装与构建成本。
- 安装后 CLI 的启动、单文件及 batch 表现。
- 通过公共 `lib` 调用的稳定转换性能和阶段热点。

正式性能验收采用两个独立窗口，每组 3 次预热、30 次测量，baseline/candidate 交错运行；记录 p50/p95、峰值 RSS、CPU、首次输出、吞吐、安装体积、机器及编译指纹。小输入增加库内批量测量，避免计时分辨率失真。

门槛为：

- 全部日常与样例回归通过，零新增质量失败。
- 同指纹逐例延迟和 RSS 不超过 10% 回退；不得用整体平均掩盖退化。
- 安装体积增加必须有对应能力收益；工具链升级单独建立基线。
- PDF 完整契约下，以**延迟降低至少 50%、峰值 RSS 降低至少 30%**为本轮优化目标；未达标如实记录，不承诺尚未测得的收益。
- 数据不足或波动过大标记为结论不足，不能按通过处理。

### 可靠性与平台

- 覆盖 Path/Text/Bytes/同步及异步 Reader、stdin、单文件、batch、收集/Sink。
- 覆盖短读、提前 EOF、取消、写失败、缓存预算、解压炸弹、深度、循环引用、损坏结构和临时文件清理。
- 两个平台运行持续 60 分钟混合负载，以及并发 1/2/4 个独立转换进程；RSS、文件描述符、临时文件不能随已处理文档数持续增长。
- 保留适用的完整单测、Native debug/release、接口、覆盖率、变异、sanitizer/fuzz 门槛；工具不可用时明确标为未验收。
- 全量回归和性能不能以公共 façade 的少量 smoke 测试替代。

## 5. 实施阶段、并行方式与交付

| 阶段 | 交付与退出条件 |
|---|---|
| **P0：证据与契约冻结** | 固定主仓、外仓、语料、依赖和机器指纹；修复验收器；跑出真实当前基线；登记已有失败及无效历史比较 |
| **P1：Native 工具链与安装** | 固定可复现工具链和依赖；解决旧 manifest 不兼容；本地与固定 Git 提交可安装，独立 Native 消费模块可导入；清除 Wasm 产品分支 |
| **P2：单一执行与预算基座** | 完成异步 Reader/Registry/pull/Sink、显式关闭、预算和临时文件管理；文本、ZIP、PDF 代表路径通过 |
| **P3：公共解析与格式迁移** | 完成 XML/编码/ZIP 整合，迁移 Office/ODF/EPUB；逐项处理 HTML、Markdown、结构化文本、MIME 和其他格式；每项独立差分验收 |
| **P4：PDF 与算法优化** | 完成按需对象、单次解释/解码、文档缓存、逐页生命周期及几何修复；提交阶段 profile 和同质量收益 |
| **P5：完整 RC** | Linux/macOS 两轮完整回归、性能和持续负载；安装与库消费验收；更新文档、接口迁移、能力表和回退记录 |
| **P6：发布后确认** | 正式发布单独执行；使用精确版本完成 `moon install` 和全新项目库消费，确认发布包与候选一致 |

并行安排为三条实现线：执行与验收基座、公共解析/Office、PDF。共享输入、预算、解析协议先冻结；同一工作目录的 MoonBit 构建串行，独立实验在隔离模块运行。

每个改动按“复现或契约 → 最小实现 → 差分 → 性能 → 删除冗余”推进。旧实现只保留在冻结提交和对照产物中，不长期保留双生产路径。

外部源码或算法移植记录确切来源、revision、许可证、涉及片段及测试；不兼容的代码不复制。运行时依赖、算法移植、参考 oracle 分别记录结论，不以采用社区包数量衡量成功。

最终交付包括更新后的[升级计划](/Users/winter/Documents/Moonbit/markitdown/docs/architecture/native-performance-plan.md)、能力与迁移说明、可复现 `.mbtx` 验收入口、完整语料结论、性能报告及最小依赖/FFI 清单。发布前只能声明“候选验收通过”，精确版本安装验收完成后才能声明正式交付通过。
